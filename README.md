## Getting Started & How to Build

This website is built using **VitePress**.

### Prerequisites
**Node.js 26** — the version CI builds with. Every release up to 25 has reached end of life.

### 1. Install Dependencies
Run the following command in the root directory to install all required dependencies:
```bash
npm ci
```

### 2. Type Check and Test
CI runs both of these before it builds, so it is worth running them first:
```bash
npm run typecheck
npm test
```
`npm run typecheck` checks the `.ts` files and the `.vue` components with `vue-tsc`.
`npm test` runs the whole suite once; use `npm run test:watch` to rerun tests as you edit.

### 3. Run Locally (Development Server)
To start the local development server with hot-reload:
```bash
npm run dev
```
The local server will start, typically at `http://localhost:5173/`.

### 4. Build for Production
To compile and build the static assets for production deployment:
```bash
npm run build
```
This compiles the site into the `docs/.vitepress/dist` directory.

### 5. Preview Production Build
To preview the compiled production build locally:
```bash
npm run docs:preview
```

## Project Structure

```
docs/                      Everything published to the site
├── .vitepress/config.mts  Site config; the sidebar is generated by walking
│                          docs/notes and docs/tools, so a new page shows up
│                          without being registered anywhere
├── index.md               Home page
├── notes/                 Notes, one directory per category
│   └── notes.data.ts      Supplies the /notes index page
├── tools/                 One markdown page per tool
│   └── tools.data.ts      Supplies the /tools index page
├── components/            Vue components that the pages mount
├── lib/                   Plain TypeScript behind the tools; no Vue, no DOM
└── utils.ts               Shared helpers behind both index pages
test/                      Checks that span the whole repository
.github/workflows/         CI: type check -> test -> build -> deploy to Pages
```

A new tool is a markdown page in `docs/tools/`, a component in `docs/components/`,
and whatever logic is worth testing on its own in `docs/lib/` — which keeps the
component thin and the logic reachable from a test.

### Tests

The suite is in three layers.

1. **Logic** — `docs/lib/*.test.ts`, `docs/utils.test.ts`. Pure functions, no DOM,
   so most of what a tool does can be covered here.
2. **Components** — `docs/components/*.test.ts`. Mounted with a DOM, for the wiring
   a logic test cannot reach: state, events, lifecycle.
3. **Repository-wide** — `test/`. Links and heading anchors across every markdown
   file including this one, and the contracts every tool page has to keep.

The first two sit next to the code they cover. The third lives in `test/` because it
belongs to no single file, and it applies to pages added later without being told
about them.
